# Competitor Teardown

## When to use
Researching the market or planning a feature.

## Inputs
App name (as {{COMPETITOR_NAME}}), version, capture date, sources (store page, screen recording, public docs).

## Steps
1. Identity: name, version, date, sources.
2. Core loop: intake, explanation shape, practice, retention.
3. Pedagogy honesty: does it show steps, check answers, admit uncertainty, or just give answers?
4. Monetization as published, with date.
5. Compliance surface: permissions, ads, data collection, age handling, integrity posture.
6. Verdict: learn, avoid, or gap.

## Outputs
One file using `../../templates/competitor-teardown.md`.

## Gates
Record only what was observed with source and date. No guessing at private economics.
