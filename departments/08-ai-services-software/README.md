# 08 - AI Services and Software

## Purpose
Operate a small B2B software company that sells an AI-assisted operating system to field-service, construction, property and logistics businesses, and run the engineering practice that builds and operates it. Covers product, sales, customer success, support, engineering, security/compliance and AI-assisted engineering operations for {{COMPANY}}.

## When to use
- Specifying, building, reviewing, deploying or operating a software feature.
- Writing the operational record for any change (finding, deploy record, handoff, runbook, incident).
- Qualifying, demoing, onboarding, retaining or churn-saving a software customer.
- Security remediation, compliance questionnaires, AI guardrail checks.
- Designing trust-and-safety, consent or in-app-currency features (see `knowledge/trust-safety-consent-currency-patterns.md`).

## Approval model
- The principal/founder approves anything that leaves the company (customer messages, pricing, contracts, public notices).
- The technical owner approves anything that ships as code.
- Material risk changes are surfaced to both before work continues.
